# 向导

**向导**是一个 bash 脚本，带人一步步走完一套手工流程：这套流程人工做起来枯燥，每次向 AI 重新解释也枯燥。它会逐个打开网址，明确说清点什么、复制什么，收集这些值，写到该写的地方（`.env`、GitHub 密钥），每一步都确认一次，并显示还剩几步。它可能用来配置第三方服务、跑一次性迁移，或者把项目从一种状态搬到另一种状态。

舒适的交互已经由 [template.sh](template.sh) 解决：分步进度、确认关卡、跨平台打开网址（包括 WSL）、隐藏输入密钥、幂等的 `.env` 写入、`gh secret`／`gh variable` 写入，以及收尾总结。**你的任务只是把流程的范围理清，并写出各个阶段。** 每个向导里 `STAGES` 标记之上的那部分库代码完全一样，这种一致性正是要点：绝不要手动改动它。

向导默认是一次性的：为跑一次而生成，保存在临时路径或 `scripts/` 下，事情办完就删。只有当用户希望得到一条可以留在仓库里反复使用的初始化路径时，才提交它。

## 流程

### 1. 理清流程范围

弄清楚这个人必须做的每一个手工步骤，以及沿途收集的每一个值。先读仓库，不要开口就问：

- 做初始化配置时：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置，以及 `.github/workflows/*`（每一处 `secrets.*` / `vars.*` 引用都是向导必须产出的值）。
- 做迁移或状态转换时：当前状态、目标状态，以及两者之间不可逆的操作。

然后把按顺序排列的阶段清单和每个阶段产出的值给用户看，并确认：他们可能增加、删掉或调整顺序。

**完成标准：** 每个阶段都按顺序命名，并且对每个收集的值都清楚 (a) 人从哪里拿到它，(b) 它写到哪里（`.env`、GitHub 密钥、两者都写，或者都不写；有些阶段只是纯粹的操作），(c) 它是密钥（隐藏输入）还是公开值。

### 2. 梳理每个阶段的路径

对每个阶段写出人要走的确切路径：打开哪个网址，在那里做什么，值显示在什么地方，填进哪个变量：例如“后台 → Developers → API keys → Reveal test key → 复制”。凡是你不确定当前界面或确切命令的地方，就明说并去问用户或查文档：绝不要编出可能并不存在的步骤。

**完成标准：** 每个阶段都能追溯到陌生人也能照做的具体说明。

### 3. 编写向导

把 `template.sh` 复制到目标路径。用每个步骤一个 `stage` 替换掉示例阶段，按依赖顺序排列。使用库里的辅助函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。把 `TOTAL_STAGES` 设为你写出的阶段数量。

守住模板立下的标准：先打开网址再索取对应的值，凡是密钥都用 `ask_secret`，每个要保留的值都用 `write_env`，只给 CI 真正需要的值用 `set_secret`，任何不可逆操作之前都要 `confirm`。每个 `stage` 都会清屏，只显示当前这一步：让一个阶段只做一件聚焦的事，免得人需要的内容滚出屏幕。不要改动标记之上的库代码。

### 4. 验证并交付

- `bash -n <script>`；如果有 `shellcheck` 就运行它。
- `chmod +x <script>`。
- 不要自己端到端跑一遍：它会打开浏览器并停下来等人输入。改为静态检查：第 1 步列出的每个值都被收集了，而且落到了第 1 步所说的位置；每个 `set_secret` 的名字都与 CI 中某个 `secrets.*` 引用完全对应。
- 告诉用户怎么运行它。如果这是一条可反复使用的初始化路径，就提交它，并在 README 里链接过去，好让下一个人直接运行脚本，而不是去问 AI。
