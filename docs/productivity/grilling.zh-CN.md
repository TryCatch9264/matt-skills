## 它做什么

`grilling` 是那套访谈循环：在任何人依据一份计划、一个决定或一个想法行动之前，先把它们压一遍。它把主题画成一棵**设计树**：每个决定都分出挂在它下面的决定，然后逐个分支访谈你，直到没有一个假设还留在没说出来的状态。

它不是一次问一个问题，也不是一次问完所有问题。每一**轮**问的是整个**前沿**：所有前提已经定下来的决定，仅此而已。两个问题如果互相依赖，就绝不同处一轮；一个挂在尚未解决的答案上的问题，属于更靠后的一轮。你的回答定下决定，前沿向外推进，下一轮就问因此解除阻塞的那些。十三个问题通常在约三轮里问完，而不是十三轮。

## 什么时候用它

打 `/grilling`，或者在任务合适时由[代理（agent）](https://www.aihero.dev/ai-coding-dictionary/agent)自动取用。它是拷问这一族里唯一模型调用的[技能（skill）](https://www.aihero.dev/ai-coding-dictionary/skill)，所以你很少亲手打它。通常是你*确实*打了的某个技能替你跑它。

直接打 `/grilling` 得到的是裸访谈，别的没有。想要更多的时候：

| 你手上是什么 | 用 |
| --- | --- |
| 你不在工作目录里工作 | [grill-me](https://aihero.dev/skills-grill-me)：同一场[会话（session）](https://www.aihero.dev/ai-coding-dictionary/session)，挂一个代理绝不会自己触发的名字 |
| 你在工作目录里 | [grill-with-docs](https://aihero.dev/skills-grill-with-docs)：同一场会话，过程中写 `GLOSSARY.md` 和 ADR |
| 一次会话装不下的大工作 | [wayfinder](https://aihero.dev/skills-wayfinder)：它画一张地图，并在决策工单里跑拷问 |
| 说话定不下来的问题：某样东西该长什么样、该有什么手感 | [prototype](https://aihero.dev/skills-prototype)：先做一次性版本，再回来 |
| 你自己的技能需要一个访谈 | 从那里调用 `/grilling`，而不是另写一套访谈 |

## 轮、前沿，以及谁做决定

这个技能建立在三个想法上。

**设计树**是主题的模型：决定，以及挂在决定下面的决定。**前沿**是前提全部定下来的那批决定：这是代理目前唯一能问的问题。一**轮**是一个前沿，整轮问出、整轮答完。

在一轮之内，每个问题有固定格式：编号加标题放在 `❓` 后面，然后是正文，然后是代理自己推荐的答案，单独放在一行 `➡️`。这个格式让你按编号回答一轮（“1 是，2 选第二个，3 不行，因为……”），而不必把问题引回来。这个格式有一个已知问题。推荐有时是*反对*问题本身的措辞的，所以同意那条推荐意味着对问题回答“不”。遇到这种情况，就回答推荐，并说清你是在回答推荐。

设计的另一半是事实与决定的分工。事实是技能自己的活。当前沿上的某个问题需要[环境（environment）](https://www.aihero.dev/ai-coding-dictionary/environment)能定下来的东西时，代理派一个[子代理（subagent）](https://www.aihero.dev/ai-coding-dictionary/subagent)去查，而不是问你。这一轮不等那份研究；只有依赖它的那些问题才等。决定是你的，代理必须等你。一个跑着 `grilling` 却自己回答自己决定的代理，已经破坏了这个技能。前沿为空时会话结束。然后代理等你确认理解已经共享，才按你们商定的去行动。

前沿有一个局限。代理靠判断来选它，不是从图上算出来。所以它可能把两个问题放进同一轮，后来才发现一个答案本该改变另一个。唯一的防护是你告诉它。下一轮会把受影响的分支重新打开。

## 常见问题

**我能改回一次问一个问题吗？**
能，而且相当一部分读者就是这样用的。把下面这段加进你全局的 `CLAUDE.md`：

```
When grilling, ask one question at a time.
```

并不是每个人都更喜欢按轮提问的默认做法。读得慢的人、用第二语言工作的人，或者用顺序格式帮助自己集中注意力的人，都说一次一个问题对他们更好。这个退出选项是受支持的设置，不是变通办法。

**`/batch-grill-me` 去哪了？**
进了这个技能。按轮提问短暂地作为单独技能发布过，后来并入 `grilling` 本身，于是所有建立在它之上的东西（`grill-me`、`grill-with-docs`、`triage`、`wayfinder`）一次都得到了它。没有 `batch-grill-me` 可装，也没有单独的串行技能；上面那行 `CLAUDE.md` 就是回到一次一问的办法。

**一次问一整轮，那我早先的回答本该引出的问题不就没了吗？**
这是对轮次最常见的反对，前沿回答它。一轮里只包含互不依赖的问题，所以一轮里任何答案都不会让同轮里另一个问题失效。你的回答仍然改变它们之后的东西，因为代理每一轮都从头推一遍。确实会丢一点，但比“一次问完所有问题”所暗示的要少。见上面前沿的局限。

**它问完了问题就开始动工。**
确认关卡就是为这个存在的。技能在你说理解已共享时才算完成，而不是前沿为空时。更弱更快的[模型（model）](https://www.aihero.dev/ai-coding-dictionary/model)仍会跳过这个关卡。用户在低投入或非前沿模型上报告得最多，那些模型把“访谈直到理解共享”压成几个问题加一份提纲。如果你的模型这样，可靠的修法是在你自己的 `AGENTS.md` 或 `CLAUDE.md` 里加一行，告诉代理未经许可不要实现。

**它自己回答了自己的问题，没有问我。**
那是这次运行的缺陷，也是技能正文要把事实和决定分开的原因。它最常发生在另一个技能跑 `grilling` 来解决一张工单时，代理把那个任务当成了继续往前推的许可。同一条约束也是没有异步模式的原因。有人要求过一个变体：读一条 GitHub 议题，然后发布一份汇总的决定备忘录。那是另一个技能，因为一场没人回答的拷问会话产出的只是代理的意见，不是你的。

**我能不能限制问题数量？**
不能，而且设置上限是有意排除在范围之外的。有的计划需要三个问题，有的需要五十个；固定上限要么把难的那个截断，要么在容易的那个上显得随意。预期的控制手段是自然语言。让它收尾，或者停下来按现状接受计划。如果一场会话跑得特别长，原因通常是范围太大；把工作拆开，逐块拷问。

**我单独装了 `grill-me`，结果什么都不发生。**
`grill-me` 是一个一行技能，整个正文就是“跑一场 `/grilling` 会话”，所以它也需要装上这个技能。`grill-with-docs` 同样如此，而且它还额外需要 [domain-modeling](https://aihero.dev/skills-domain-modeling)。装整套就能避开这个问题；选择性安装就意味着也要把基础技能装上。

**`grill-with-docs` 跑了，但它从没加载 `grilling`。**
这是一个真实缺陷，仍未修复，用户在不同的 [harness](https://www.aihero.dev/ai-coding-dictionary/harness) 和模型上都报告过。一个技能提到另一个技能，并不能可靠地让那个技能被加载，而 `grill-with-docs` 提到了两个。症状是一场什么都在一次问完、没有推荐的会话，说明模型在临时凑一场访谈，而不是在跑这一套。直接问代理它有没有加载 `grilling` 和 `domain-modeling`，通常能把它拉回来。

## 它在生效的表现

- 一轮以编号列表到来，每个问题在单独一行 `➡️` 上带推荐，你能按编号答完一整轮。
- 一轮里没有任何问题需要先得到同轮另一个问题的答案。
- 后面的轮次问到第一轮不可能问到的东西。
- 它自己去查事实（读文件、派子代理），而不是问你一件它本可以查清的事。
- 后台跑着的研究不会拖住这一轮；只有依赖它的那些问题在等。
- 它在结尾停下来，请你确认理解已共享，而不是开始干活。
- 问题数量保持很多，而轮次数量保持很少。

## 它在哪里合用

`grilling` 是一个**基础**，不是一个你去排期的步骤：访谈技法的单一事实来源，只放一处，好让每个需要访谈的技能都来取用它，而不是另造一套。它的两扇用户调用前门是 [grill-me](https://aihero.dev/skills-grill-me) 和 [grill-with-docs](https://aihero.dev/skills-grill-with-docs)，而主构建链起始于 `grill-with-docs`，在 [to-spec](https://aihero.dev/skills-to-spec) 之前。[wayfinder](https://aihero.dev/skills-wayfinder) 跑它来解决决策工单，[triage](https://aihero.dev/skills-triage) 跑它把一份含糊的报告拷问成可用的，[improve-codebase-architecture](https://aihero.dev/skills-improve-codebase-architecture) 在你挑中一个要加深的候选之后跑它走那棵树。不确定哪个入口合适时，[ask-matt](https://aihero.dev/skills-ask-matt) 会帮你导航。
