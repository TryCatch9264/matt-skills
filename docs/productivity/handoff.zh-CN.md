## 它做什么

`handoff` 把你正在进行的对话压缩成一份**交接文档**：一个 Markdown 文件，写到操作系统的临时目录而不是工作区里，一个新的[代理（agent）](https://www.aihero.dev/ai-coding-dictionary/agent)读它就能接手这项工作。

它给你的是**可携性**，不是压缩，所以这个技能比听上去要窄。只有当工作必须*移动*时才需要文件：换到新的 [harness](https://www.aihero.dev/ai-coding-dictionary/harness)、新目录、交给同事，或者分出支线任务。如果没有东西要移动，你就不需要交接。留在[会话（session）](https://www.aihero.dev/ai-coding-dictionary/session)里、`/clear`、[子代理（subagent）](https://www.aihero.dev/ai-coding-dictionary/subagent) 和 `/compact` 覆盖了通常的阶段结束情形，而 `/compact` 覆盖它的次数比这个技能多。

## 什么时候用它

通过打 `/handoff` 调用；代理不会自己去用它。附一句下一个会话是做什么用的，技能就按那个目的来写文档。

触发条件有四个，也只有四个：

| 情形 | 为什么需要文件 |
| --- | --- |
| 换 harness（Claude → Codex） | 新 harness 看不到旧的[上下文（context）](https://www.aihero.dev/ai-coding-dictionary/context) |
| 换到别的目录或仓库 | 原型目录是常见情形 |
| 把工作交给同事 | 他们需要有东西可读 |
| 分出在阶段中途发现的支线任务 | 你继续干活，另一个代理接走这条支线 |

其他情况（同一个 harness、同一个目录、你刚做完[拷问（grilling）](https://www.aihero.dev/ai-coding-dictionary/grilling)要进入实现），用 `/compact`。[ask-matt](https://aihero.dev/skills-ask-matt) 里有覆盖阶段边界上全部五个选项的有序判断树。

## 很多人漏掉的是分叉用法

这个技能的描述读起来像会话恢复：写个摘要，这边结束，那边续上。那样读，它就像个更差的 `/compact`，于是大家跳过它。值得知道的是分叉那个用法。你**留在自己的会话里**，把已积累上下文的一份副本交给并行工作的第二个代理。

绕道跑 [prototype](https://aihero.dev/skills-prototype) 用的就是这个。你正处在一场深入的设计对话里，撞上一个只有跑代码才能定下来的问题，而你又不想把好不容易建立起来的这条线程花在找答案上。交接给一个原型会话，拿到答案，再把答案交接回来，并从原来那条线程引用它。工作来回两趟，你原来的对话仍然活着，你什么都没重新解释。

阶段边界上的五个选项里有三个保留的东西不同：`/compact` 保留你的意图，`/clear` 什么都不保留，`/handoff` 保留工作移动的能力。

## 什么会带过去，什么不会

文档承载正在进行的线索（手上在做什么、为什么、下一步是什么），再加上一节**建议技能**，点出下一个代理该用哪些技能。技能写文件之前会先对密钥脱敏。

它有意不承载任何已经写下来的东西。文档按路径或 URL 引用规格说明、计划、ADR、议题、提交和 diff，绝不复制它们。这样文件保持小，而已定的细节留在一个地方，而不是两份会互相跑偏的副本。

## 常见问题

**交接还是压缩？**
除非有东西要移动，否则用 `/compact`。留在同一个任务上是压缩，不是交接。当 harness 和目录不变、而你需要留在循环里，阶段边界那棵树多数日子会落到 `/compact`。`/handoff` 并不会总结得更好。它的优势在于结果是文件，能带去 `/compact` 到不了的地方。

**那压缩、清空和交接到底差在哪？**
三者各自保留不同的东西。`/compact` 压缩当前上下文并在新窗口里继续，所以你的意图活下来。`/clear` 清空窗口，从零开始。当你身后的一切都可以丢时这是对的，而如果不是，清掉就找不回来了。`/handoff` 写一份可移走的文件，所以工作能在搬到别处之后活下来。三者都把**[一手来源（primary source）](https://www.aihero.dev/ai-coding-dictionary/primary-source)**（真实发生过的对话）变成**[二手来源（secondary source）](https://www.aihero.dev/ai-coding-dictionary/secondary-source)**（它的摘要）。继续是唯一不这么做的选项，这就是为什么先把它排除掉。

**我的交接文件去哪了？**
它去了临时目录，这是关于这个技能被报告最多的问题。技能把它解析为 `$TMPDIR`，否则 `/tmp`（Windows 上是 `%TEMP%`），但路径很长。把路径要回来，继续之前记下它。用临时目录是有意的，因为交接是一份在途文档，不是你维护的产物。临时目录也不耐久，下面一个问题会讲。

**我的交接要在会话之间消失了。**
有些环境会在会话之间清空临时目录（被报告的是 Codex），重启也会清空 `/private/tmp`。如果下一个会话不是在一小时内开始，或者在另一个 harness 下开始，那就在文件写出来之后马上自己复制到别的不易被清空的地方。对文档*指向*的东西同样适用：如果一份派发指令引用了临时目录里的其他文件，下一个代理就跟不过去。

**我该怎么把它交给下一个代理？**
打开新会话，把路径指给它：读这个文件，然后继续。指向文件，而不是把摘要粘贴进一条 shell 命令。当你把它插值进 `claude "<summary>"` 时，shell 会把含反引号或 `$(...)` 的摘要弄坏。结果通常是静默截断而不是报错，于是新代理拿着不完整的说明开工，而且没有任何东西告诉你。

**这和 `/branch`、`--fork-session`，或者内置的 `/handoff` 一样吗？**
相似，不完全相同。`/branch` 在这里不是已发布的技能；`/handoff` 是标准名称。分叉继承一份精确的上下文副本；这个技能产出的是有针对性的压缩，瞄准一个明说的下一个任务，写成文件。分叉就够用的时候（同一台机器、同一个 harness、同一个目录），分叉更省事。当目的地在分叉去不了的地方时，文件是更好的选择。

**什么时候该把东西放进 `CLAUDE.md`？**
问它下个月是否仍然成立。`CLAUDE.md` 是关于项目的常设上下文，每个会话都加载，不管相关与否。交接讲的是一件正在进行的工作，那件事落地之后它就没用了。如果你在反复解释同一个事实，它属于 `CLAUDE.md`。一件没做完的任务属于交接。

**它抓到了做什么，没抓到为什么。**
这个批评有道理，而且人们常提。两件事有帮助。把理由交代给它（告诉它下一个会话是做什么用的），技能就会保留与*那个*相关的推理，而不是把它压平。另外留意会话从未验证过的自信断言，例如“X 没做过”或“Y 完成了”。下一个代理信任这份文档，不会再去核对，所以一个被写成事实的猜测会成为之后一切事情的错误前提。交接之前自己读一遍，把任何只是假设的东西降级。

**为什么做成技能而不是斜杠命令？**
两种都行，适合不同情况。做成技能，它就通过和这里其他东西一样的安装路径发布和更新，便于分享。让它不被代理自行触发的是它的 frontmatter，而不是这个机制。

## 它在生效的表现

- 文档只占那场对话的一小部分，规格说明、议题和 diff 在里面以路径和 URL 出现，而不是复制过来的文本。
- 你可以在不打开原会话的情况下冷读它，就知道下一步该做什么。
- 新代理直接开始干活，而不是让你重新交代一遍环境。
- 分叉的情形里，你回来时原来的会话毫无变化。
- 建议技能一节点出的，正是你自己本来会去用的那个技能。
- 里面没有任何密钥、词元或口令。

## 它在哪里合用

`handoff` 是一个**随时可用的独立技能**。它工作在会话之间，而不是构建链内部。它是一个窄技能，在阶段边界上你会用得比其他四个选项少。最亲近的邻居是 [prototype](https://aihero.dev/skills-prototype)，因为原型住在自己的目录里，去一趟再回来正是这个技能的用场。当你在边界上拿不准该继续、清空、交接、委派还是压缩时，[ask-matt](https://aihero.dev/skills-ask-matt) 里有给这五个选项排序的判断树，也会带你在这套技能的其他部分导航。
