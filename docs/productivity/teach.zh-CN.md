## 它做什么

`teach` 把你运行它所在的目录变成一个长期的教学工作区，并用简短的自包含 HTML 课程，跨多次[会话（session）](https://www.aihero.dev/ai-coding-dictionary/session)教你一个主题。

它不凭[模型（model）](https://www.aihero.dev/ai-coding-dictionary/model)已有的知识来教。它把[参数化知识（parametric knowledge）](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge)当作不可信。教之前，它先找高可信度的资源，记进 `RESOURCES.md`，并在每节课里引用它们。它也是[有状态](https://www.aihero.dev/ai-coding-dictionary/stateful)的。使命、资源、课程、你已学到东西的记录，全都在这个目录里以文件形式存在，所以下一场会话从这些文件继续，而不是从上一场对话的残余继续。

## 什么时候用它

通过打 `/teach` 调用；[代理（agent）](https://www.aihero.dev/ai-coding-dictionary/agent)不会自己去用它。

当学习本身就是这个项目时用它：一门语言、一个框架、一个你刚加入的代码库、瑜伽、着色器、一门认证考试。它不是用来顺手解释一个东西的工具。

| 你想要什么 | 用什么 |
| --- | --- |
| 花几周学一个主题，会话不断积累 | `teach` |
| 在你已经在的会话里解释一个想法 | 就在那个会话里问 |
| 代理的上一条消息没被听懂，想让它重新讲 | [wait-what](https://aihero.dev/skills-wait-what) |
| 磨利你已经有的思考，而不是获取新材料 | [grill-me](https://aihero.dev/skills-grill-me) |
| 让一个后台代理读[一手来源（primary source）](https://www.aihero.dev/ai-coding-dictionary/primary-source)并留给你一份带引用的文档 | [research](https://aihero.dev/skills-research) |
| 想学拷问中途冒出来的东西，又不打断这场[拷问（grilling）](https://www.aihero.dev/ai-coding-dictionary/grilling) | [handoff](https://aihero.dev/skills-handoff) 到一个教学工作区，在那里跑 `teach` |

## 前提条件

`teach` 建的是一个目录，不是一个文件；技能假定一个工作区一个使命，所以在一个你愿意专门交给单一主题的地方运行它。别把它放进你正在工作的项目里。独立的仓库是最好的家，比全局的 `~/.learnings/` 目录或者正在工作的项目本身都好。独立仓库还能让你把课程提交上去，团队就是这样共享它们的。

那个目录里积累什么：

| 路径 | 装什么 |
| --- | --- |
| `MISSION.md` | 你为什么学这个。其他每个文件都依赖它。它缺失时，`teach` 做的第一件事就是访谈你直到有了它 |
| `RESOURCES.md` | 它据以教学的、核实过的来源，分成知识与见识（社群） |
| `lessons/*.html` | 编号课程：教学的基本单元 |
| `reference/*.html` | 压缩的速查表、算法、术语表：你会反复回来看的文档 |
| `learning-records/*.md` | 类 ADR 的笔记，记录你确实掌握了什么，用来判断下一课教什么 |
| `assets/*` | 可复用组件，从一个共享样式表开始，让课程看起来像一门课 |
| `NOTES.md` | 你说过的教学偏好 |

关于这份清单两点说明。术语表适合多数主题，但技能带了一个 `GLOSSARY-FORMAT.md`，而 `SKILL.md` 已经不再链接它，所以你只有主动要才会得到一份（[议题 #559](https://github.com/mattpocock/skills/issues/559)）。这些都落在你运行 `/teach` 的那个目录里。

## 存储强度，不是流畅度

用来思考的词是**存储强度**：长期留存，与之相对的是**流畅度**，也就是你读的时候感觉像精通、一周后就消失的当下回忆。`teach` 通过合意难度建立前者：提取练习、间隔、交错。知识在先。那个阶段难度跟你作对，因为它吃掉了你理解所需的工作记忆。然后 `teach` 用紧的反馈回路训练技能，那个阶段难度是工具。

有两样东西决定你学到什么。**使命**（你想要它的具体真实理由）是每节课的基础。没有它，课程变得空洞，也没有东西决定下一步教什么。从使命和学习记录出发，`teach` 在你的**最近发展区**里挑下一课：够难，要费力气，但又不至于超得太远学不了。

存储强度也是技能顶回来而不是附和你的一种理由。需要**见识**（真实世界的判断）的问题，会得到一个尝试性的回答，然后被指向一个你可以去验证它的社群。技能不让你跳过测验。一位用户报告说他说了句“非常感谢”，被告知那轮训练还没做完。

## 课程、参考与组件

**课程**是一个自包含的 HTML 文件，短到一次坐下就能完成，扣住使命，给你一个可触摸的成果。它引用来源，推荐一份你自己去读的一手材料，并链接到兄弟课程和参考文档。

你很少回头去看一节课，但你会回头去看参考文档。所以一节课的短形式（语法表、算法、体式序列、术语表）属于 `reference/`，而不是埋在引入它的那节课里。

课程由 `assets/` 里的**组件**搭成：样式表、测验组件、模拟器、绘图辅助。复用是默认做法。代理写课程之前先读 `assets/`，用已有的东西来搭。任何第二节课程可能用到的新东西，它都会写成组件，而不是内联。共享样式表是每个工作区的第一个组件，它让课程看起来像一门课，而不是一堆互不相关的页面。

## 常见问题

**它把文件放哪了？我的最后落在 `~/.claude/skills` 里。**
在你运行 `/teach` 的那个目录里（[#377](https://github.com/mattpocock/skills/issues/377)）。

**我该留在一个会话里，还是每节课开一个新会话？**
三种做法都行：留在同一个会话里、在新会话里重新调用 `/teach`、或者在同一文件夹里开一个新会话。每节课是它自己的一次调用。课程状态住在文件夹里，不在对话里。常见做法是在工作区里开一个新会话，然后说 `/teach next lesson for <topic>`。

**我怎么知道它没在教我它编出来的东西？**
光凭技能自己说，你不知道。你读一手来源。`teach` 没可靠到可以不核对就信，任何建立在 LLM 上的技能都是如此。那些根基（`RESOURCES.md`、每节课里的引用、每节课推荐一份一手材料）让核对一节课变得便宜。但它不消除核对的需要。这种失败发生过：一位学 2x2 魔方的用户拿到了编出来的、解不开的转动序列。遇到这种情况，检查模型、harness、投入等级和来源。风险在记号精确的流程型领域最高，在输出可以立刻验证的地方最低，比如你能跑的代码。

**正确的测验答案永远在第一个选项。**
好几个人在 Sonnet、Opus 和 GLM 上确认过这一点，至今未修。`SKILL.md` 现在要求每个答案词数相同。那去掉了另一种线索（正确选项以前是唯一推理完整的那个），但对位置只字未提。一位贡献者试了一个在指令层面修位置问题的办法，九节课里正确答案仍然 33 次全落在 A 位（[#335](https://github.com/mattpocock/skills/issues/335)）。所以真正的修法是 `assets/` 里一个在渲染时打乱答案的测验组件，而不是更好的措辞。在它发布之前，别管答案位置。`assets/` 目录是你的，可以改，所以你可以要一个本地修法：在渲染时打乱的组件。

**它假定我已经懂一些东西，还用了从没定义过的术语。**
这是最常见的真实抱怨。没有评估环节。`teach` 从使命和学习记录推断你的水平，而第一次会话里没有学习记录。一位在 wayfinder 流水线里跑它的用户说得直白：“它从没做拷问来确定我的起点，所以对我的已知做了很多假设。” 另一个人报告课程用了未定义的行话，还有一节讲他们硬件的课只讲了硬件能做什么，从没说它不能做什么。两件事有帮助：在第一条消息里说明你已有的知识和你的缺口，以及某节课不对味时出声纠正水平，因为纠正会变成一条学习记录，引导下一节课。一个明确的知识评估步骤是长期的功能请求（[#725](https://github.com/mattpocock/skills/issues/725)），不是已发布的行为。

**它做间隔重复吗？它知道什么时候该停止教学吗？**
第一个不做，第二个不可靠。技能围绕间隔和交错设计课程，但没有任何东西安排复习，也没有 Anki 或日历集成。用户常同时要这两样。一个相关的缺口是退出条件。正如一位用户说的，`teach`“擅长做下一节课，但不那么擅长知道什么时候该停下来转去复习或者真实练习”。如果你想要复习或训练而不是新材料，就主动要；技能不会自己提出切换。

**它只对代码有用吗？**
不是。被报告的使用多数在编程之外：韩语、日语敬语、钢琴、吉他、桌游设计、OpenSCAD、电影情节、Azure 和 CCNA 认证、大学考试，还有八岁和十岁的孩子拿到关于密室逃脱和火蝾螈的可打印小册子。技能里没有哪部分是编程专属的。使命、资源、最近发展区和训练在任何领域都以同样的方式工作。在代码范围内，用户报告最大的价值是在一个不熟悉的代码库或新团队的技术栈里找到方向，而不是从零学一门语言。

**我该用哪个模型跑它？**
没有标准答案，而被报告的差异很大。用户报告更高的[推理投入（reasoning effort）](https://www.aihero.dev/ai-coding-dictionary/effort)产出的课程比中等设置更好。一位用户用 Copilot CLI 配 Codex 跑同一个技能，得到一个 30 行的 HTML 卡片，而 Claude Code 产出了一节完整课程。如果你的组织允许在那里加技能，它在 Claude Cowork 里不改就能跑。如果课程出来得单薄，先换模型、[harness](https://www.aihero.dev/ai-coding-dictionary/harness) 或投入等级，再去重写提示。

## 它在生效的表现

- 在空目录里它做的第一件事是访谈你为什么想要这个，而不是产出一节课。
- `RESOURCES.md` 在课程之前先填满，而且每节课都点出一份值得你自己去读的一手材料。
- 课程里的论断带外链。一节没有引用的课，就是技能在凭记忆教。
- 一节课一次坐下就能完成，并让你能做一件以前做不到的事。
- 在这个文件夹里开一个新会话说“下一课”，课程继续而不是重来。
- `learning-records/` 在长，课程不再重复教你已经展示过的东西。
- 课程看起来像一门课：它们链接 `assets/` 里的样式表，而不是各自带一份。
- 一个需要判断的问题，会让你被指向论坛、subreddit 或课程，而不只是一个答案。

## 它在哪里合用

`teach` 是一个**随时可用的独立技能**。它不是构建链上的一步，与工程流程不共享任何产物；它在自己的目录里工作，只要你还在学这个主题。

它唯一真正的邻居是 [handoff](https://aihero.dev/skills-handoff)。两者合起来回答“我正在被拷问一件我不懂的事，怎么办？”不要停下拷问去学。`/handoff` 到一个教学工作区，在那里用 `/teach` 学这个主题，然后回去从你中断的地方继续。附近的替代品是 [research](https://aihero.dev/skills-research)，用于你想要的是一份带引用的文档，而不是课程和留存。不确定哪个技能或流程合适时，[ask-matt](https://aihero.dev/skills-ask-matt) 会带你在整套技能上导航。
