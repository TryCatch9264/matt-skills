## 它做什么

`improve-codebase-architecture` 扫描代码库寻找**加深机会**。也就是那些浅模块（接口几乎和它藏起来的东西一样复杂）可以变深的地方。它把这些写成一份自包含的 HTML 报告，然后把你挑中的那一个[拷问](https://www.aihero.dev/ai-coding-dictionary/grilling)透。

它从不改代码。整次运行产出一场对话和操作系统临时目录里的一个 HTML 文件。重构你以后另开一个[会话（session）](https://www.aihero.dev/ai-coding-dictionary/session)走正常构建流程去做。所以它是勘察，不是重构工具，因此你可以拿它跑在一个你还没准备好动的代码库上。

两道过滤防止报告变成泛泛的清理建议。第一，每个候选都必须通过**删除测试**：如果把这个模块删掉，它的复杂度是移到一个更小的接口后面，还是散到各个调用方身上？只有前者才配一张卡片。第二，除非你把它指向某个具体区域，它会先读最近的提交历史，把扫描集中在经常变化的路径上。没人碰的代码里的加深，是一笔永远收不回成本的重构。

## 什么时候用它

通过打 `/improve-codebase-architecture` 调用；[代理（agent）](https://www.aihero.dev/ai-coding-dictionary/agent)不会自己去用它。

它不是主构建循环里的一步。你定期跑它，攒出更多改进代码库的工作。人们在四种情况下用它：

| 情形 | 怎么用 |
| --- | --- |
| 日常维护 | 每隔几天跑一次，或者有空的时候跑，免得结构在功能之间退化。 |
| 大构建之前 | 把它指向[规格说明（spec）](https://www.aihero.dev/ai-coding-dictionary/spec)，问“我们怎么让这个改动变容易？”这是对它最有效的提示。 |
| 存量代码审计 | 拿它跑一个大而杂乱、或者[凭感觉写的（vibe-coded）](https://www.aihero.dev/ai-coding-dictionary/vibe-coding)仓库，看看它是什么形状。 |
| 遗留代码的测试工作 | 在给不可测的代码写测试之前，用它找出缺失的接缝。 |

容易和兄弟技能混淆的地方：

- 想设计一个你已经选好的模块，用 [codebase-design](https://aihero.dev/skills-codebase-design)。这个技能找出该动的模块，`codebase-design` 是你设计它的地方。
- 一项一次会话装不下的大工作，用 [wayfinder](https://aihero.dev/skills-wayfinder)。
- “这个具体的东西坏了”，用 [diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs)。当真正的发现是没有合适的接缝把缺陷固定住时，它会把你送回这里。

## 前提条件

跑它不需要任何前提。如果存在 `GLOSSARY.md` 或 `docs/adr/` 里的 ADR，它会读，并使用你领域自己的名词。于是一个候选读起来是“加深 Order 录入模块”，而不是“重构 FooBarHandler”。

它写两个地方。报告写到仓库之外的 `<tmpdir>/architecture-review-<timestamp>.html`。在拷问循环里，它给 `GLOSSARY.md` 添加或磨利术语，文件不存在就创建它。它也会提议把被否掉的候选记成 ADR，免得以后的运行再建议一遍。

## 深度，以及找它的那份报告

技能建立在一个想法上：**深度**。深模块把大量行为放在一个小的、稳定的接口后面。浅模块通过一个几乎和底下的代码一样宽的接口暴露自己的实现。报告找三种浅的形式：

- 只为可测试性抽出来的纯函数，而真正的缺陷在调用方怎么用它（缺少**局部性**）。
- 跨越**接缝**泄漏的模块。
- 不开五个文件就理解不了的一个概念。

对每一个，它提出能修好它的加深方案。

每个候选是一张卡片：涉及的文件、摩擦、平实的解决方案、以**局部性**和**杠杆**表述的收益、一张改前／改后图，以及一个强度徽标。

| 徽标 | 对你意味着什么 |
| --- | --- |
| `Strong` | 删除测试明确通过，摩擦是真实的。认真对待这些。 |
| `Worth exploring` | 加深看起来合理，但回报取决于代码接下来往哪走。 |
| `Speculative` | 为了完整才列进来。大部分可以忽略。 |

报告以一条**首选建议**结束，也就是它最先会做的那个候选。然后技能停下来，问你想深入哪一个。到这一步你什么都没决定，代码也没变。

## 你挑中一个之后发生什么

你挑中一个候选后，一场[拷问（grilling）](https://aihero.dev/skills-grilling)会话在它上面开始。它会覆盖约束、接缝背后放什么、哪些测试能留下来、加深后的接口该长什么样。那场会话的产出是一个决定，不是一个 diff。之后就套用正常流程：把决定带进 [to-spec](https://aihero.dev/skills-to-spec)，然后 [to-tickets](https://aihero.dev/skills-to-tickets)，然后 [implement](https://aihero.dev/skills-implement)。

## 常见问题

**它为一个想法拷问了我一小时，而不是给我看选项。我能关掉吗？**

能。调用时说出来（“不要拷问我，只给我报告”）。这是关于这个技能最常见的抱怨。有位用户喜欢它，觉得它是“一种方便地得到透彻改进分析的办法”，但在拷问循环加上之后，觉得它“基本没法用”。在他们的会话里，它先提出一个方案，然后问“几十上百个问题”。设计意图是报告在先，只有在你选中的候选上才开始拷问。但更弱的[模型（model）](https://www.aihero.dev/ai-coding-dictionary/model)会直接跳到就它想到的第一个想法做访谈。那个线索里的结果因模型差异很大。这是一个未关闭的议题，技能还没有成文的免拷问模式。

**报告打开是没样式的裸 HTML，也没有图。发生了什么？**

报告从 CDN 加载 Tailwind 和 Mermaid，所以打开时需要网络。有东西挡住那些脚本，页面就会坏掉且不报错。在被报告的那个例子里，一个安全钩子要求 SRI 哈希。代理加上了，但 CDN 送给浏览器的字节和送给那个算哈希的 `curl` 的字节不同，于是浏览器拦了脚本。离线和受限环境有同样的问题。代理看不到这一点，因为它从不渲染页面。变通办法是改为要求内联 CSS 和手工搭的 SVG 图，不要 CDN 那一套。这是一个未关闭的议题。

**它给了我十二个候选。我该在同一个会话里过完，还是开新的？**

一个会话一个候选。如果你在一场对话里过好几个，[上下文窗口（context window）](https://www.aihero.dev/ai-coding-dictionary/context-window)会同时装满报告、拷问、领域模型修改和代码改动。报告只是一个临时文件，所以往前带的是候选，不是那个文件。挑一个，拷问它，把决定带进 `/to-spec`。把其余的变成[工单（ticket）](https://www.aihero.dev/ai-coding-dictionary/ticket)，以后单独捡起来。把选中的改进写进规格说明，而不是直接去实现。人们常问这个，而技能自己没写任何对应的流程。

**我该怎么提示它？**

用你接下来要建的东西提示它。如果有大构建要来，把它指向规格说明，问“我们怎么让这个改动变容易？”不带提示的运行会自己去找热点。日常维护这样就行，但给个方向能让报告可执行。

**它在大型遗留代码库上能用吗？**

部分能。它在缺少一致结构的大型既有代码库上效果不错，也是任何时候做完一次性结构整理之后推荐的维护工具。但项目失控的用户报告说它“帮了一点，但还是不太行”。一位维护八年老代码库的开发者报告说模型在原地打转，而同一个技能在整洁的仓库上产出干净的图。针对那种情况还没有专门的 `/refactor` 技能。如果代码库没有共享词汇，先跑 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 建一套。那通常会让这个技能的产出好得多。

**这和 `/codebase-design` 有什么不同？**

`/codebase-design` 是一份参考，不是会话驱动器。它提供词汇（模块、接口、深度、接缝、适配器、杠杆、局部性），这个技能用的是它。如果你把一个新代理的任务设成 `/codebase-design`，它会以已知的方式失败。它自己没有流程可循，于是代理自己发明一个，重新探索代码，跑很久才问你点东西。跑这个技能，让它去用那个。

**它会不会告诉我代码库没问题？**

很少，所以开始之前先知道这一点。技能存在的意义是输出发现，所以它倾向于产出候选，而不是断定一切都没问题。用强度徽标来纠正这一点。如果报告里每个候选都是 `Speculative`，那就是什么都没找到。

**它在 Codex 或其他 harness 里能用吗？**

部分能。探索那一步直接点了 Claude Code 的 `Agent` 工具配 `subagent_type=Explore`。没有那个工具的 [harness](https://www.aihero.dev/ai-coding-dictionary/harness) 可能会跳过并行探索，而不是用它自己的对应功能。技能仍然能跑，但扫描没那么彻底。有人提议过改成与 harness 无关的写法，但没有合并。

**我怎么在 TypeScript 里真正实现深模块？**

技能没有给出好的答案。人们常要一份 `TYPESCRIPT.md`，用具体的文件和模块布局落实这些原则，而它不存在。技能告诉你加深该放在哪、接缝背后放什么。把它变成包或目录结构，得你自己做。

## 它在生效的表现

- 候选点出你领域的概念，而不是生造的类名：“Order 录入模块”，不是“FooBarHandler”。
- 候选在你最近编辑过的文件里，而不是仓库里没人碰的部分。
- 运行期间没有任何代码变化。唯一的新文件是临时目录里的那份 HTML 报告。
- 它在报告之后停下来，问你想深入哪个候选。它不会自己继续。
- 每张卡片用局部性或杠杆解释回报，并说明哪些测试会变简单，而不只是“这样更干净”。
- 你因为一个长期有效的理由否掉某个候选时，它提议记一条 ADR，免得下次运行再建议它。

## 它在哪里合用

`improve-codebase-architecture` 是**定期维护**。你每隔几天跑一次，在任何链条之外，攒出工作，而不是去做工作。它的邻居：

- [codebase-design](https://aihero.dev/skills-codebase-design) 拥有每个候选都会用的深度与接缝词汇。
- [grilling](https://aihero.dev/skills-grilling) 在你选定一个候选之后走决策树。
- [domain-modeling](https://aihero.dev/skills-domain-modeling) 在你做决定的过程中让 `GLOSSARY.md` 和 ADR 保持最新。

它的产出是一个想法，这个想法从 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 或 [to-spec](https://aihero.dev/skills-to-spec) 回到主构建流程。它在主流程尾部的对应物是 [retro](https://aihero.dev/skills-retro)。这个技能改进代理所工作的代码，而 `retro` 在一次构建之后改进它周围的环境（检查、规范、引导文件）。哪个技能适合某种处境，[ask-matt](https://aihero.dev/skills-ask-matt) 是覆盖整套技能的导航器。
