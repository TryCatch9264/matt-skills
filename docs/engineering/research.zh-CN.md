## 它做什么

`research` 通过阅读掌握答案的来源来回答一个问题，然后在仓库里留下一份带引用的 Markdown 文件。它只依据**[一手来源（primary source）](https://www.aihero.dev/ai-coding-dictionary/primary-source)**工作：官方文档、源代码、规格说明、第一方 API。它把每个论断都追回到掌握它的那一手来源，所以能拿到 API 自己的文档时，它不会去复述某篇博客对那个 API 的说法。

它不在对话里直接回答你。产出是一个文件，写在仓库已经放这类笔记的地方，每个论断都带链接。你拿到的是一份可以对着反应、可以交给另一个代理、也可以直接扔掉的文档，而不是一个[会话（session）](https://www.aihero.dev/ai-coding-dictionary/session)结束就消失的答案。

## 什么时候用它

打 `/research`，或者在一个任务变成读材料的苦活时由[代理（agent）](https://www.aihero.dev/ai-coding-dictionary/agent)自动取用。

当下一步是从工作目录之外*查清某件事*（第三方 API 的行为、规格说明怎么说、某个版本的说法是否成立），而你不想让自己这条线程停下来去读，就用它。你需要什么决定用哪个技能：

| 你需要什么 | 用 |
| --- | --- |
| 某个决定正在等的外部事实 | `research` |
| 通过访谈*和你一起*做出的决定 | [grilling](https://aihero.dev/skills-grilling) |
| 写进 `GLOSSARY.md` 和 ADR 的长效架构决定 | [grill-with-docs](https://aihero.dev/skills-grill-with-docs) |
| 查清某个做法在你们代码库里行不行 | [prototype](https://aihero.dev/skills-prototype) |
| 一次会话装不下的计划 | [wayfinder](https://aihero.dev/skills-wayfinder) |

`research` 与 `grill-with-docs` 的分界在于**带回来的东西能放多久**。研究产出的是短命事实，比如这个库的鉴权机制这周是什么行为。ADR 记录的记录是你长期保留的决定。如果你产出的是一个决定而不是一个事实，那就是在[拷问（grilling）](https://www.aihero.dev/ai-coding-dictionary/grilling)，不是在研究。

## 委派出去的苦活

阅读作为**后台代理**运行。它把每个论断追到一手来源、写一个 Markdown 文件、回报结果，而你继续干你的活。研究是你委派出去的苦活，不是你外包出去的思考。你拿到一份可以用来拷问、规划或设计的文档，而决定仍然由你做。

没有任何机制阻止这个后台代理再派生一个自己的后台代理。这是这个技能被记录得最充分的问题。

文件放哪里由仓库决定，不由技能决定。它遵循已有的笔记约定。如果没有这样的约定，它挑一个合理的位置并告诉你。每次运行写一个文件。

## 常见问题

**它派生了第二个研究代理。这应该发生吗？**

不应该。这是一个未修的缺陷，[issue #530](https://github.com/mattpocock/skills/issues/530)。技能让它的调用方起一个后台代理，但没有限定代理类型。于是调用方起了一个 `general-purpose` 代理，那个代理有 `Agent` 工具和同样的指令，于是又把指令走了一遍。一位报告者测得单个研究任务在三次重叠运行里大约花了 450k [词元（token）](https://www.aihero.dev/ai-coding-dictionary/token)，而重复的那份晚了半小时才结束，用户看不到它。这也在 Claude Code 之外发生。用户确认在 Codex 配 GPT-5.6-sol 时也有同样的嵌套。没有已发布的修法。有用户给本地安装的副本打了一行补丁，告诉已经是[子代理（subagent）](https://www.aihero.dev/ai-coding-dictionary/subagent)的代理自己把活干完；这有帮助，但那只是一条指令，不是结构性修复。你调用技能之后，盯着后台任务列表，把重复的那个停掉。

反面的失败也会发生。如果你自己的全局指令禁止代理再往下委派，后台代理就会拒绝这个任务，而技能什么都不做，也不告诉你。

**文件该放哪，我该提交它吗？**

技能把文件放在仓库已经放笔记的地方，没有更多意见。社区的看法基本一致：留 ADR，不留研究文件。一条关于这个问题的 Discord 讨论说得最清楚：“ADR 留。其他都在做完之后归档或删掉。否则它就变成工作的杂物，而且当你已经偏离了规格说明／研究时，它还会毒化以后的仓库阅读。”研究文件记录的是写下那天的实情，所以过时的那份比没有更糟。权衡下来，这些文件不该进 git，也没有标准存放处。人们改用 Obsidian、独立的知识仓库，或者议题跟踪器。

**什么算“高可信度”的一手来源，由谁判定？**

由[模型（model）](https://www.aihero.dev/ai-coding-dictionary/model)判定。技能点出合乎要求的来源*种类*（官方文档、源代码、规格说明、第一方 API），没有白名单、没有域名门槛、没有验证环节。这是技能最初提出时最响的反对意见，至今没人公开回答：“五个研究子代理指向垃圾，只会让你更快拿到五个自信的错答案。你怎么把关什么算高可信度来源？”你唯一的保护是每个论断上的引用。随手跟两三个。如果它们落到对这个东西的转述而不是它本身，这次运行就失败了。

**之后的会话会复用之前那次运行的发现吗？**

不会。没有任何机制自动加载过去的研究文件。文件留在仓库里，直到人或某个技能指向它。这是设计早期受到的最强挑战：“价值在于那份 Markdown 变成代理以后会重读的上下文，而不是取回本身。一次写入就死掉的文件只是个花哨的搜索。”已发布的技能没有解决这一点。实践中，只有当你自己把文件喂进下一步时它才有用：附到规格说明上、引用进拷问会话、让一张[工单（ticket）](https://www.aihero.dev/ai-coding-dictionary/ticket)指向它。

**为什么不直接让代理去读文档？**

可以，而在两行提示就够用的地方，那正是这个技能取代的做法。技能给你两样提示给不了的东西。它跑在后台，所以你这次会话的[上下文（context）](https://www.aihero.dev/ai-coding-dictionary/context)保持干净。而且一手来源约束和带引用的文件产出每次都一样，不取决于你当时怎么措辞。与 [harness](https://www.aihero.dev/ai-coding-dictionary/harness) 自带的深度研究模式相比，差别在文件和一手来源规则，不在搜索。如果一个小问题用两行提示就能解决，就用两行提示。

**它什么时候停止阅读？**

这个技能没有停止条件。这表现为两条看似相反、其实同因的抱怨：代理研究得过深，以及代理把一个主题铺得很广却漏掉唯一要紧的细节。一位实践者说：“深度研究技能有时候太深了。而让代理去研究，结果往往是漏掉关键细节。”范围得你来定。一个窄而可答的问题（一个 API、一个行为、一个版本说法）回来得远好于“研究一下 X”。

**`/wayfinder` 创建了研究工单。那些我自己解决吗？**

不用，现在它替你触发。在 v1.1 之后尚未发布的改动里，画地图的会话会为每张研究工单起一个 `/research` 子代理并行运行。每个都把自己的发现记在一条一次性的 `research/<name>` 分支上，并从工单给出一个[上下文指针（context pointer）](https://www.aihero.dev/ai-coding-dictionary/context-pointer)。研究工单是 wayfinder“每会话一个工单”规则的唯一例外，因为它们是 [AFK](https://www.aihero.dev/ai-coding-dictionary/afk) 的：没有东西在等你。一个已知问题：以后删掉那条分支会弄坏工单里的上下文指针。

## 它在生效的表现

- 你自己的会话还在继续。如果你坐在那儿看它读，那说明委派没有真正发生。
- 后台任务只多了一个。多出一个名字几乎相同的，那就是嵌套缺陷。
- 仓库里多了一个 Markdown 文件，在仓库本来放笔记的目录下，代理告诉你路径。
- 里面每个论断都带链接，随手跟两个都落到官方文档、规格说明或源文件本身，而不是别人对它的转述。
- 光靠这份文件你就能做出被困住的那个决定，不必自己回去查来源。

## 它在哪里合用

`research` 是一个随时可用的独立技能。它喂给思考类技能，不是构建链上的一步。你把它的文件*带进*流程。[grilling](https://aihero.dev/skills-grilling) 和 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 在已经掌握事实时问得更锐利，[to-spec](https://aihero.dev/skills-to-spec) 可以对着它做综合。[wayfinder](https://aihero.dev/skills-wayfinder) 是唯一直接调用它的技能：它用 `/research` 子代理解决地图上的每张研究工单。整张地图见 [ask-matt](https://aihero.dev/skills-ask-matt)。
